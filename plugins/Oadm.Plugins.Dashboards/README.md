# Dashboards (`oadm.dashboards`)

Core plugin (+ `.Client`), rail page **Dashboards** (group Monitoring, icon `gauge`), **off by default**, switchable. Live
values of OADM's events (mostly device triggers) and live video on saved dashboards, like a small Grafana: a dashboard is a
grid of widgets, each showing one value of one device. Spec and decisions: `docs/dashboards.md`.

## Decisions

| Topic | Decision |
|---|---|
| Data | The server part subscribes to every event the server handles (`ICorePluginContext.EventSubscriptions`) and keeps the latest per event type and device in memory (`ValueStore`): on / off for an on / off event, the last value of each field (an event without a field keeps the field's value), the time. At most 100,000 keys, the least recently updated dropped first, O(1) per event. Memory only: turned off or restarted it starts empty; the subscription's snapshot brings the events that are on. It never talks to a device. |
| Fields | An event offers its values at once: **Active** (`@active`, yes / no) for an on / off event, then its declared `EventField`s (a device trigger declares every value with the type from the device's event list), then values it sends without declaring them, once seen. Kind: the declared `EventField.Kind`, for text the last 20 values received suggest Number (all numbers, invariant culture; `0` / `1` stay Number) or Yes / no (all true / false / yes / no / on / off). `FieldValues`. |
| Old values | `ValueSnapshot.Stale`: the event no longer exists ("Event no longer exists"), its plugin is off ("Device triggers is turned off"), the trigger's "connection lost" (`<type id>.lost`) is on for the device ("Connection lost"), or OADM's own status event of the device is on ("Unreachable", "Credentials required", "Certificate changed"). OADM's own status events and the lost events are never old themselves. The widget is dimmed with the reason below. |
| Watching | The page watches the keys of the widgets in its **open** tabs (`watch` with its own id, renewed every 10 s; `unwatch` when the page closes; forgotten 30 s after the last renewal). Changes of watched keys are pushed as event `values` every 250 ms at most (several events of one widget in between: one update with the latest). A status or "connection lost" change marks the device's watched values; a type change marks all. The catalog (event `catalog`) is pushed at most once a second when a new field was seen or the types changed. |
| Storage | Like Live View: plugin setting `dashboards` (JSON, enums as text), shared by every user, every change pushed (event `dashboards`). A save of an older version is refused ("Another user changed the dashboard X meanwhile. Click Cancel and make your changes again."); an unreadable stored list is kept as `dashboardsUnreadable`. |
| Grid | The shared `ui:TileGrid` with `DashboardsPluginInfo.Layout` (20 x 20 cells, at least 2 x 2, never overlapping); a dropped value takes up to 4 x 4; Add cameras sizes the cameras so all of them fit (16: 5 x 5 each, one: 8 x 8), smaller where the grid is full. |
| Limits | 50 widgets per dashboard, of them 16 live videos; 200 dashboards; names 1..64 (widget names may be empty); unit 10 characters; 10 thresholds; sizes 10..100 % of the widget; colors and icons only from `WidgetColors` / `WidgetIcons` (theme brushes by name: dark and light both work). The server checks all of it again (`DashboardRules`). |
| Widgets | **On / Off** (icon, color and optional text per state, icon size), **Text** (font size, color; shrinks to fit, then "…"), **Number** (decimal places or as received, unit, font size, color, thresholds: the color of the highest threshold the number reaches; a value that is no number shows "Not a number" dimmed), **Live video** (the host's live video component like a Live View tile: controls closed, fullscreen with a double-click, the channel buttons; the channel chosen while editing is saved). Value widgets are transparent on the card (frame class `valueTile`); video keeps the video background. Every value widget has **Show name** (a Yes / No select, Yes by default; off, the value takes the room, the edit frame still names it). `WidgetDisplay` (no UI) decides what a widget shows; `WidgetView` draws it (`FitText`, `FitBox`). |
| Roles | "show" (automatic, Operator and Viewer), **Change dashboards** (`manage`: save, delete; Operator yes, Viewer no; both audited). Video needs "Live view"; without it the widget says "Your role does not allow live view.". |
| Page | Left card (Collapse / Expand like Live View): **Dashboards** (+ New dashboard; Edit and Delete in each row), **Events** (the available events grouped, device triggers first, each with its fields and their kind; search). Right card: Close all tabs, while editing Name / Save / Cancel / **Add cameras** (the shared picker for several devices, cameras only, those on the dashboard greyed; at most 16 live videos, the rest named below the toolbar), the tabs (`ui:PageTab`); the grid; while editing the panel of the selected widget right of the grid (a new `WidgetEditorView` per widget, a `GroupEditorView` for several). Empty states: Device triggers off ("Turn on Device triggers on the Plugins page", `ICorePluginClientContext.IsPluginOn`), no trigger yet ("Create a device trigger first." + **Open Device triggers**), no dashboard yet. |
| Editing | New dashboard opens a tab in edit mode ("Dashboard N"). An event dropped or clicked becomes a widget of its first field with the widget that fits (Number for a number, On / Off for yes / no, else Text) and opens its panel: Device (the shared picker for one device, the devices of the event; not for a server event), Value, Type (Automatic (X), Yes / no, Number, Text), Widget (only those that fit the type), Name (default "<value> · <device address>", follows the value and device until the user changes it), then the widget's settings. Every change shows in the grid at once. **Several widgets** (`DashboardTab.Selection`): a drag over empty cells draws a selection rectangle (`TileGrid.ShowSelectionArea`) and selects every widget it touches, Ctrl+click adds or removes one (no move), Ctrl+A selects all, a click on empty cells selects none. A selected widget dragged moves the whole selection by whole cells (it stops at the grid's edge and never moves onto another widget); dragging an edge or a corner of one resizes every selected widget by the same cells, selected widgets side by side making room for each other (`TryResizeSelection`; all or nothing: nothing changes when one would leave the grid, get smaller than 2 x 2 or hit another widget). The group panel (`GroupEditorViewModel`): copy and remove for all; Width and Height in cells (each widget that has room); Show name; the On / Off, Text / Number and Number settings when all selected widgets are of that kind; a setting where they differ shows "Mixed" (an empty select or field) until changed, a change goes to all of them and nothing else changes. **Copy for other devices** (the copy icon left of a widget's X while editing, `ITileGridItem.CopyCommand`, or the group panel's icon; widgets with a device): the shared picker for several devices (the widget's own device greyed, devices without video for a video widget), one copy per device with the same settings and size in the first free place of that size (`TileLayout.PlaceSized`), the device's address replacing the source's in the name (else " · address" added); as many as fit, the rest named below the toolbar ("12 of 20 copies added. ..."). Save checks the rules and that every widget of a device event has a device. |
| Devices | The pickers (Device, Copy for other devices) offer only the devices of the event: `EventTypeInfo.DeviceIds`, a device trigger's devices now (chosen, tagged, all), asked with `devices` when the picker opens (the catalog only says `hasDeviceList`); events without a list (OADM's own) offer every device. |
| Deviations from the spec | No "trigger the event once": the declared values are offered at once (the spec asked for a received event before `EventField.Kind` existed). No Cameras tree: **Add cameras** picks cameras in the device picker (a tree of thousands of cameras was too long). No **Open Plugins** button for administrators (a page cannot tell an administrator). The channel of a video widget is chosen with the picture's channel buttons, not in the panel. Added after the spec: Copy for other devices, several widgets selected and changed together, Show name, the Any device events. |

## Methods (`InvokeAsync`)

| Method | Payload | Answer | Permission |
|---|---|---|---|
| `list` | none | `DashboardList` sorted by name | show |
| `save` | `SaveDashboardRequest` {id (empty = new), name, version, widgets} | the stored `Dashboard` (version + 1) | manage |
| `delete` | `DeleteDashboardRequest` {id} | none (an unknown id is nothing to do) | manage |
| `catalog` | none | `CatalogReply` {events: typeId, name, group, source, stateful, deviceScope, available, fields, hasDeviceList} | show |
| `devices` | `DevicesRequest` {typeId} | `DevicesReply` {deviceIds, null = any device}: asked when a picker opens, so the catalog never grows with the devices | show |
| `watch` | `WatchRequest` {watchId, keys: [{typeId, deviceId}]} | `ValuesReply` with the values now; more than 5,000 keys are refused ("Too many dashboards are open. Close some tabs.") | show |
| `unwatch` | `UnwatchRequest` {watchId} | none | show |

Events: `dashboards` (`DashboardList`), `catalog` (`CatalogReply`), `values` (`ValuesReply` with the changed watched values).

## Tests

`tests/Oadm.Plugins.Dashboards.Tests`: storage, versions and every refusal; the values (each field's last value, the key
cap, old values and their reasons, reading and suggesting types); the catalog (declared values at once, refined by received ones, at most once a second);
watching (only watched values, one update per 250 ms, a page that went away); turned off keeps nothing; Perf: 50 widgets
updating 4 times a second next to 30,000 other devices. Page: what a widget shows for each kind, the empty states, a new
dashboard from an event and a camera with the panel and live values, several widgets selected, moved, sized and changed together, Add cameras up to 16, the device check, other users, roles; headless
screenshots with fake-mode video (`plugin-dashboards.png`, `-edit`, `-onoff`, `-drop`, `-empty`). Core:
`EventSubscriptionTests` (the subscription's types and their changes). Fake mode (`FakeOadmApi.Dashboards.cs`): three
sample triggers, the dashboard "Building A" and values that change every second.
