Turn on provisioning and plug in factory-new cameras. Every factory-new camera OADM finds is added to OADM and gets one
task that runs the active profile: password, AXIS OS, configuration, time, certificate, network settings and more. The
task shows in the tasks pane like every other task.

<Image src={toolbar} alt="The Devices toolbar: Add, Remove, Refresh, Export and Provisioning active with a green icon" class="screen" />

## Before you start

- You are an administrator. Operators and viewers do not see the **Provisioning** button by default.
- For **Set password** from the credential list: a password of the user root on the
  [Credentials page](../../admin/users/#credentials-page). You can also type one in the profile.
- To hand out addresses to new cameras, OADM's [DHCP server](../dhcp-server/) runs on the network they are plugged into.
  Cameras found by Discovery, Network range, Add manually or an import are provisioned too.

## Turn it on

<Steps>

1. Click **Provisioning** in the Devices toolbar, right of **Export**.
2. Click **New** and build a profile (see below). Your first profile without errors becomes the **Active profile**.
3. Turn the switch to **On**.
4. Plug in factory-new cameras.

</Steps>

<Image src={dialog} alt="Provisioning: the switch On with who turned it on, the active profile, a warning, and the profile list with New, Edit, Activate and Delete" class="screen" />

While provisioning is on, the toolbar button reads **Provisioning active** with a green icon. It stays on, also when the
server restarts, until you turn the switch to **Off**. Off starts no new task; running and queued tasks run to their
end and **Run again** still works. Cancel them in the tasks pane if needed.

The switch stays off when no profile is active or the active profile has errors. The reason shows below the switch.

<Image src={dialogOff} alt="Provisioning off: Choose the active profile first. below the switch" class="screen" />

Warnings show below the active profile, for example "The pool overlaps the DHCP server's range 10.0.0.100 to
10.0.0.199." Provisioning still works.

## Which cameras

A camera gets its task when OADM finds it factory-new (no password yet):

- by **Discovery**, also the discovery that runs in the background, **Network range**, **Add manually** or an import,
- by an address of OADM's DHCP server,
- when a camera OADM manages is reset to factory default.

OADM asks the camera itself right before the first change. A camera that is still starting is asked again for up to 2
minutes. A camera that has a password is never changed. A camera gets no second task while its task runs. Up to 8
cameras run at once; the others wait as **Queued**. A camera whose task failed gets no new task when OADM finds it again:
use **Run again**, or reset the camera to factory default.

On the Add devices page a factory-new camera shows **Ready for provisioning** instead of **Set password** while
provisioning is on and the active profile has no errors. Add it as usual: it is added without a password and its task
sets it up.

<Image src={add} alt="The Add devices page with provisioning on: Provisioning in the Action column of a factory-new camera, Set password for one at a site" class="screen" />

## Profiles

A profile is a chain of nodes that runs from top to bottom on each camera. Only one profile is active at a time.

<Image src={editor} alt="The profile editor: the chain of nodes on the left, the selected Network node's form on the right with an error below Last address" class="screen" />

<Steps>

1. In **Provisioning**, click **New**, or choose a profile and click **Edit** (or double-click it).
2. Enter a **Name**. A new profile starts with **Set password**.
3. Click the **+** below a node: the last one, or the one you selected. Search or browse the list of nodes and click one.
   It is added right after that node.
4. Click a node to see its form on the right. The **?** at the right of each field tells what to enter.
5. **Move up** and **Move down** change the order, **Remove** deletes the selected node, **Fit view** shows the whole
   chain.
6. Click **Save**.

</Steps>

**Set password** is fixed: always the first node, never moved or removed.

The profile list shows every profile with its state: **Active** or **Has errors**. **Activate**
makes the selected profile the active one, like the **Active profile** choice. **Delete** asks first. The active profile
cannot be deleted while provisioning is on. A change to a profile applies to the next tasks; running tasks keep their
copy.

### Drafts

Errors show below the field and on the node in the chain. You can still save the profile as a draft. A draft shows
**Has errors** in the profile list and cannot be the active profile until you fix it.

### Results

Every node ends with one result, shown as a step of the camera's task:

- **Success**, with what it did, for example "Password set."
- **Not needed** (a skipped step): the node does not apply to this camera, for example "Not needed: no SD card."
- **Warning**: it did its part, something is worth a look.
- **Error**, with the reason.

**Continue on error** is on for every node except Set password: after an error the next nodes still run. Turn it off to
stop the task at that node. An error at Set password always stops the task.

## Nodes

### Set password

Sets the first root password on the camera. Fixed: always first. An error here always stops the task.

- **Root password**: **From the credential list** (choose a **Credential** of the user root) or **Type a password**
  (**New password** and **Confirm password**, 1 to 64 printable ASCII characters). A typed password is added to the
  credential list when you save and is never shown again.
- Each credential shows when it was added. Administrators see the eye next to it: it shows the stored password, like the
  eye on the **Credentials** page, and every time it is shown goes into the audit log. Click it again to hide it.

After the password, OADM waits up to 2 minutes until it has read the camera with it.

- Success: "Password set."
- Warning: "OADM has not read the camera yet; the next steps may fail."
- Error: the reason.

### Network

Sets the camera's IP address, DNS servers and search domain. Every part is optional, but set at least one. The camera's
host name is never changed. The address is written last; OADM follows the camera to its new address.

- **IP address**: **Keep** (as it is now, for example from DHCP) or **From a pool**.
- **First address** and **Last address**: the pool, for example 192.168.15.10 to 192.168.15.50. In the same subnet, at
  most 4,096 addresses.
- **Subnet mask**: for example 255.255.255.0.
- **Default router**: in the subnet of the pool, outside the pool.
- **DNS servers**: optional, at most 2, separated by commas.
- **Search domain**: optional, for example site.example.com. It needs DNS servers.

A new Network node starts in the network of OADM's DHCP server (for example 192.168.15.): type the last number.

How addresses are given:

- Each camera gets the next free address of the pool. An address is skipped when a device in OADM has it, it answers on
  the network, or another camera got it already.
- Two cameras never get the same address, also when they run at the same time.
- The address is always set as a fixed address, also when the camera has it already.
- A given address stays reserved while the camera's task runs and until the camera is in OADM with it, also when
  provisioning is turned off and on. It is free again when the camera refused it or was removed from OADM.
- Keep the pool outside the DHCP server's range. An overlap is a warning in the node and in Provisioning.

Results:

- Success: "192.168.15.12 is in use, 192.168.15.13 assigned."
- Error: "The camera did not take 192.168.15.13: " with the reason. OADM keeps the camera at the address that answers.
- Error: "No free address left in the pool."

### Upgrade AXIS OS online

Installs AXIS OS from axis.com, with the MyAxis sign-in of the administrator who turned provisioning on. The checks of
[Upgrade AXIS OS](../../tasks/firmware/) apply.

- **Install**: **Newest of the camera's own track**, **Newest LTS** or **Newest of the active track**.
- **Only if older than**: optional. A version like 12.6.95. Cameras that run this version or a newer one are left as
  they are.

Results:

- Success: "AXIS OS from axis.com installed." or "Already 12.6.95."
- Error: "Sign in to MyAxis." when the sign-in is missing or expired. After a server restart: "Turn
  provisioning off and on again: the server restarted since it was turned on."

### Upgrade AXIS OS from files

Each camera gets the file for its model from the files you choose. Never a downgrade: a file older than the camera's
AXIS OS is not installed.

- **AXIS OS files**: **Choose files** uploads them to the server. Files named as Axis names its downloads, for example
  P3265-LVE_12_6_95.bin. One file per model, at most 32 files.

Results:

- Success: "AXIS OS 12.6.95 installed." or "Already 12.6.95." (same or newer AXIS OS on the camera).
- Warning: "No file for this model."
- Error: the reason of the upgrade.

### Date and time

Sets the time zone and where the camera gets its time.

- **Time zone**: choose from the list. Type a city to jump to it.
- **Time from**: **The NTP servers DHCP gives**, **These NTP servers** or **OADM's NTP server** (the
  [NTP server](../ntp-server/) of OADM, its address filled in for each camera).
- **NTP servers**: with These NTP servers. Host names or IP addresses, at most 5, separated by commas.
- **Use NTS where the camera has it**: with These NTP servers.

Results:

- Success: "Time zone Europe/Vienna, NTP 10.0.0.17.", "Time zone Europe/Vienna, NTP servers from DHCP." or "Time zone
  Europe/Vienna, OADM's NTP server."
- Error: "Time zone Europe/Vienna set. OADM's NTP server was not set: " with the reason.

### Configuration

Applies settings from a file of Export configuration in [Device configuration](../../tasks/device-configuration/), or
from a camera OADM manages, also of another model: each camera takes the settings it has. Addresses, host names,
certificates and passwords are never copied.

- **Settings from**: **A configuration file** or **A template camera**.
- **Configuration file**: a .json file of Export configuration.
- **Template camera**: **Choose camera**. It is read when the node runs and needs AXIS OS 12.5 or later. The template
  camera itself is left as it is.
- **Apply**: **Parameters**, **Action rules**, **Schedules**. At least one.

Results:

- Success: "Parameters and action rules applied." or "Parameters of the template camera applied."
- Not needed: "Not needed: this is the template camera."
- Warning: values the camera refused, listed.
- Error: for example "The template camera ACCC8E012345 has no configuration export (AXIS OS 12.5 or later)."

### Users

Adds more accounts to the camera. OADM's own account is never removed, demoted or given another password. A profile can
have several Users nodes.

- **Accounts**: **Add account** adds a row, at most 10.
  - **User name**: 1 to 14 letters and digits, each name once. root is the account of Set password.
  - **Role**: **Viewer**, **Operator** or **Administrator**.
  - **PTZ control**: the account may move PTZ cameras.
  - **Password** and **Confirm password**: typed only, 1 to 64 printable ASCII characters. Kept on the server, never
    shown again.

Results:

- Success: "Added operator and service."
- Warning or Error: per account, for example "service: " with the camera's reason.

### Certificate

Gives the camera its certificate. The camera's clock is checked first: a camera whose clock is behind gets no
certificate.

- **Certificate**: **From a PKI policy** installs a certificate of [PKI](../pki/) and turns on HTTPS.
  **EST enrollment (OADM PRO)** sets up enrollment with the [EST server](../est-server/), so the camera renews by itself.
- **Policy**: the HTTPS certificate policy of PKI that issues the certificate. With only one policy it is chosen
  already.

Results:

- Success: "Certificate installed, HTTPS on." or "EST enrollment set up."
- Error: the reason, for example "OADM PRO is not active. Nothing was changed." for EST without OADM PRO.

### 802.1X

Turns on 802.1X with the certificate, identity and CA of the PKI policy you choose. The camera's clock is checked
first.

- **Policy**: the IEEE 802.1X certificate policy of PKI. With only one policy it is chosen already.

If a chosen policy is deleted in PKI, the node says "The PKI policy no longer exists. Choose another one." and the
profile cannot be active. On a switch port that enforces 802.1X the camera answers only once it is authenticated.

Ends with "802.1X on." or an error with the reason.

### SD card

Prepares the SD card. Uses the camera's own file system.

- **Prepare**: **Format**, **Encrypt** (formats too). Choose at least one, or enter days below.
- **Passphrase** and **Confirm passphrase**: with Encrypt. At most 512 bytes. Typed only, kept on the server, never shown again.
- **Delete recordings older than (days)**: optional, 1 to 7000.

Results:

- Success: "SD card encrypted and formatted, recordings kept 30 days."
- Not needed: "Not needed: no SD card."
- Error: the reason, after what was done already.

### Autofocus

Starts the autofocus and waits until it is done, at most 2 minutes. No settings. Nothing else is changed.

Results:

- Success: "Focus found."
- Not needed: "Not needed: no remote focus."
- Error: "The camera could not find focus. Set focus by hand.", "The camera is too hot or too cold to move the lens." or
  "The autofocus did not end within 2 minutes."

### VAPIX commands

Runs commands of the [VAPIX Commander](../vapix-commander/) library with their values, in order. The Commander's checks
apply.

- **Commands**: **Add command** adds a row, at most 50.
  - **Command**: choose from the library. Commands marked dangerous and commands that need a password or a file cannot
    run in a profile.
  - The command's own fields follow, each as in VAPIX Commander.

Results:

- Success: "Ran Set overlay text and Set stream profile."
- Warning: "Not on this camera: Set stream profile." The camera lacks that command; the others still run.
- Error: the reason of the commands.

## Tasks

Each camera's task is named **Provision with** and the profile, for example "Provision with Lobby cameras". Its steps are
"Check that the camera is new" and one step per node, for example "Set the password", "Set the network settings", "Set
the date and time". **Details** in the tasks pane shows each step with its result and the task's log. The nodes start
the tasks of their areas (Upgrade AXIS OS, Device configuration and others); those show in the tasks pane too.

### Run again

Select a failed **Provision with** task and click **Run again** in the tasks pane. A new task runs only the failed steps
and those that did not run, in order, with the same profile. A camera that failed the check that it is new is checked
again and runs everything.

<Image src={runAgain} alt="The tasks pane with a failed Provision with task selected and Run again next to Details" class="screen" />

## What it never does

- It never changes a camera that already has a password.
- It never changes the DHCP server's settings.
- It never removes or demotes the account OADM uses on the camera.
- It does not run at [sites](../../sites/overview/): cameras found through a site node are added as usual and keep
  **Set password**.
