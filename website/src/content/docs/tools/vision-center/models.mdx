A model is a file that finds objects in a picture (**Detection**: boxes with a class and a score) or names what a picture
shows (**Classification**: one class and a score). OADM ships no model: an administrator uploads them. Models are shared by
all pipelines of the server.

## Formats OADM reads

Models are ONNX files (`.onnx`) that take one colour picture. OADM recognises the kind of model from its outputs when you
upload it:

| Format | Models | Notes |
|---|---|---|
| **YOLO** | YOLOv5, YOLOv8, YOLO11 and later, exported to ONNX | OADM removes the double boxes itself |
| **YOLO with suppression** | YOLO models exported with the double boxes already removed | At most 1,000 boxes per picture |
| **DETR** | DETR of Facebook Research, also as Hugging Face exports it | Class names from **COCO, 91 ids** |
| **RT-DETR** | RT-DETR, D-FINE and YOLO26 as Hugging Face exports them (onnx-community) | Class names from **COCO, 80 classes** |
| **RF-DETR** | RF-DETR of Roboflow | Also the segmentation models: they find boxes |
| **DETR with labels** | RT-DETR, D-FINE and other models that give boxes, scores and labels | Upload a labels file |
| **Classification** | Models with one score per class | For the [Classify](../nodes/#classify) node. Upload a labels file |

OADM also chooses how the picture is fitted to the model's input: with bars (YOLO), stretched (RF-DETR, RT-DETR, DETR with
labels, classification) or scaled with its shape kept (DETR).

## Models that work

**Tested** means the model ran in OADM's tests on real pictures. **Should work** means it has a format OADM reads but was
not tested yet. The download links go to the files of their makers.

## Upload a model

Uploading needs the permission **Manage vision models** (administrators).

<Image src={upload} alt="The Models card with three models and an upload at 40 %" class="screen" />

<Steps>

1. In the **Models** card on the left of the page, click **Upload model**.
2. Choose the `.onnx` file. To give the classes their names, choose a labels file (`.txt`, one name per line, one line
   per class) together with it.
3. The row shows **Upload** with its progress (**Cancel** stops it), then a ring while OADM checks the model.
4. The model shows with its kind, input size, classes and size, for example
   `Detection · 576x576 · 91 classes · 121 MB`. Hover over it for the pipelines that use it, the SHA-256 and the time of
   one call on the CPU and on the graphics card.

</Steps>

A new model is named after its file. The ⋯ menu of a model has **Rename**, **Class list** and **Delete**. **Delete** is
refused while a pipeline uses the model, for example **Used by 2 pipelines: Gate 1, Lane 2.**

### The model check

Before OADM keeps a model, it opens it and runs it once on a blank picture. A model that fails is not kept and the row
says why, for example **This model cannot run here: it needs data in other files. Export it as one file.** See
[Troubleshooting](../troubleshooting/#model-upload) for every reason.

### Change how a model is read

The model check picks the format, the fit and the scaling for you. When boxes land in the wrong place or the classes
make no sense, open the model's **⋯** menu > **Settings**:

| Setting | Choices | When to change it |
|---|---|---|
| **Format** | YOLO, YOLO with suppression, YOLOX, DETR, RF-DETR, DETR with labels, RT-DETR, Classification | The model was read as another family. OADM refuses a format the outputs do not fit |
| **Fit** | Letterbox, Stretch, Keep shape and pad | Boxes are shifted or squeezed. YOLO uses Letterbox, RF-DETR and RT-DETR Stretch, DETR Keep shape and pad |
| **Scaling** | 0 to 1, ImageNet, 0 to 255, BGR | Scores stay low or classes are nonsense. Ultralytics models use 0 to 1, DETR and most classifiers ImageNet, YOLOX 0 to 255 BGR |
| **Input width**, **Input height** | 32 to 2048, in steps of 32 | Only for a model without a fixed size. Larger finds smaller objects and takes longer |

### Models are data, never code

A model runs only with the standard operations of ONNX Runtime. OADM refuses a model that needs code of its own or
data in other files. For you this means:

- A model exported with the standard tools of PyTorch or Ultralytics works.
- A model that needs a custom operator, for example from TensorRT or an own plugin, is refused. Export it again without.
- A model exported into several files is refused. Export it as one file.

## Class names

A model knows its classes by number. OADM names them, in this order:

1. The names inside the model file, as Ultralytics writes them.
2. A labels file uploaded with the model.
3. A built-in class list, when the model has 91 or 80 classes.
4. Else `Class 0`, `Class 1` and so on.

### Class lists

A class list is a set of names for a model's classes. You choose it on the model, never on a node, because the numbers
belong to how the model was trained.

| Class list | Fits |
|---|---|
| **COCO, 91 ids** | DETR and RF-DETR trained on COCO. 80 names; the 11 unused numbers are never shown |
| **COCO, 80 classes** | YOLO trained on COCO, the same names without gaps |
| Your own lists | Any model with as many classes as the list has names |

The section **Class lists** below **Models** shows them. **New** creates a list: a **Name** and the names, one per line.
Built-in lists have **View**; your own **Edit** and **Delete**.

To change a model's names, open **Class list** in the model's ⋯ menu. It offers **Own names** and the lists with the
model's number of classes.

<Image src={classList} alt="The Class list dialog of a model with 2 classes: Own names, the note No class list has 2 names, and the names helmet and no helmet" class="screen fit" />

- A list in use cannot change its number of names: **Used by models with 2 classes. Keep 2 names.**
- A list in use cannot be deleted.
- **Detect objects** shows the model's list below the model, for example **Class list: COCO, 91 ids**.
- At most 50 own lists.

## Export your own model

Export with one picture as the input, in floating point numbers, as one file. A fixed input size is read from the model;
for a free one OADM uses 640 x 640.

### YOLO

With Ultralytics (`pip install ultralytics`):

```sh
yolo export model=yolo11n.pt format=onnx
```

Your own trained model works the same way (`model=best.pt`). The class names travel inside the file.

### DETR

With PyTorch 2.5 or later:

```python
import torch

model = torch.hub.load('facebookresearch/detr', 'detr_resnet50', pretrained=True).eval()
picture = torch.zeros(1, 3, 800, 800)
torch.onnx.export(model, picture, 'detr-r50.onnx', input_names=['images'],
                  output_names=['pred_logits', 'pred_boxes'], opset_version=17, dynamo=False)
```

OADM names the classes with **COCO, 91 ids**. The ready
[DETR R50 file](https://huggingface.co/Xenova/detr-resnet-50/resolve/8be7ab59ff663484ee9ba2e8d8f267330d5ad03e/onnx/model.onnx)
saves you the export.

### RF-DETR

Your own trained RF-DETR: the [rf-detr-onnx](https://github.com/PierreMarieCurie/rf-detr-onnx) project exports it with
`uv run export.py --checkpoint your-model.pth`.

### Classification

Any model with one picture in and one score per class out, for example a classifier of PyTorch exported with
`torch.onnx.export` like DETR above, with one output. Upload a labels file with it. OADM gives a classifier a 224 x 224
input when the file leaves the size open, and scales the picture as ImageNet models are trained, except for Ultralytics'
files, which say so in the file.

## Limits

| What | At most |
|---|---|
| Models | 20 |
| Size of one model | 500 MB |
| All models together | 4 GB |
| Classes of a model | 1,000 |
| Input size | 4,096 pixels per side |

## Backups

A backup keeps the model list, its settings and your class lists, never the model files. After a restore a model shows
**Missing** and its pipelines say **Upload the model Gate people again.** Upload the same file: the model comes back with
its settings.
