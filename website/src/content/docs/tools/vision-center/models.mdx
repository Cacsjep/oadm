A model is a file that finds objects in a picture (**Detection**: boxes with a class and a score) or names what a picture
shows (**Classification**: one class and a score). OADM ships no model: an administrator uploads them. Models are shared by
all pipelines of the server.

## Formats OADM reads

Models are ONNX files (`.onnx`) that take one colour picture. OADM recognises the kind of model from its outputs when you
upload it:

| Format | Models | Notes |
|---|---|---|
| **YOLO** | YOLOv5, YOLOv8, YOLO11 and later, exported to ONNX | OADM removes the double boxes itself |
| **YOLOX** | YOLOX of Megvii, as its releases export it | OADM removes the double boxes itself |
| **YOLO with suppression** | YOLO models exported with the double boxes already removed | At most 1,000 boxes per picture |
| **DETR** | DETR of Facebook Research, also as Hugging Face exports it | Class names from **COCO, 91 ids** |
| **RT-DETR** | RT-DETR, D-FINE and YOLO26 as Hugging Face exports them (onnx-community) | Class names from **COCO, 80 classes** |
| **RF-DETR** | RF-DETR of Roboflow | Also the segmentation models: they find boxes |
| **DETR with labels** | RT-DETR, D-FINE and other models that give boxes, scores and labels | Load a labels file when you import it |
| **Classification** | Models with one score per class | For the [Classify](../objects/#classify) node. Load a labels file when you import it |

OADM also chooses how the picture is fitted to the model's input: with bars (YOLO, YOLOX), stretched (RF-DETR, RT-DETR, DETR with
labels, classification) or scaled with its shape kept (DETR). To export a model of your own, see
[Export your own model](../export/).

## Models that work

**Tested** means the model ran in OADM's tests on real pictures. **Should work** means it has a format OADM reads but was
not tested yet. The download links go to the files of their makers.

## Import a model

Importing needs the permission **Manage vision models** (administrators). **Import model** in the **Models** card opens a
wizard in three steps.

<Steps>

1. **Model**: choose the `.onnx` file and click **Next**. The file goes up with its progress, then OADM checks the
   model. A file OADM cannot run says why below it.
2. **Settings**: **Model detected** and what OADM found, for example `Detection · 576x576 · 91 classes`, the name and
   the **Model family** OADM found (YOLOv8, RF-DETR, an ImageNet classifier and others). The settings are already set
   for the model, each with a green check; change the family or a setting only if your model was made differently (see [The settings of Import model](../export/#the-settings-of-import-model)).
3. **Labels**: the class list, or the model's own names. **Load labels file** fills them from a `.txt` file with one
   name per line. Click **Import**.

</Steps>

The model shows in the card with its kind, input size, classes and size, for example
`Detection · 576x576 · 91 classes · 121 MB`. Hover over it for the pipelines that use it, the SHA-256 and the time of one
call on the CPU and on the graphics card. **Cancel** removes the file again.

A new model is named after its file. The ⋯ menu of a model has **Rename**, **Settings**, **Class list** and **Delete**. **Delete** is
refused while a pipeline uses the model, for example **Used by 2 pipelines: Gate 1, Lane 2.**

### The model check

Before OADM keeps a model, it opens it and runs it once on a blank picture. A model that fails is not kept and **Import model**
says why below the file, for example **This model cannot run here: it needs data in other files. Export it as one file.** See
[Troubleshooting](../troubleshooting/#model-upload) for every reason.

## Class names

A model knows its classes by number. OADM names them, in this order:

1. The names inside the model file, as Ultralytics writes them.
2. A labels file loaded in **Labels** when you import the model.
3. A built-in class list, when the model has 91 or 80 classes.
4. Else `Class 0`, `Class 1` and so on.

### Class lists

A class list is a set of names for a model's classes. You choose it on the model, never on a node, because the numbers
belong to how the model was trained.

| Class list | Fits |
|---|---|
| **COCO, 91 ids** | DETR and RF-DETR trained on COCO. 80 names; the 11 unused numbers are never shown |
| **COCO, 80 classes** | YOLO, RT-DETR and D-FINE trained on COCO, the same names without gaps |
| Your own lists | Any model with as many classes as the list has names |

The section **Class lists** below **Models** shows them. **New** creates a list: a **Name** and the names, one per line.
Built-in lists have **View**; your own **Edit** and **Delete**.

To change a model's names, open **Class list** in the model's ⋯ menu. It offers **Own names** and the lists with the
model's number of classes.

<Image src={classList} alt="The Class list dialog of a model with 2 classes: Own names, the note No class list has 2 names, and the names helmet and no helmet" class="screen fit" />

- A list in use cannot change its number of names: **Used by models with 2 classes. Keep 2 names.**
- A list in use cannot be deleted.
- At most 50 own lists.

## Limits

| What | At most |
|---|---|
| Models | 20 |
| Size of one model | 500 MB |
| All models together | 4 GB |
| Classes of a model | 1,000 |
| Input size | 4,096 pixels per side |

## Backups

A backup keeps the model list, its settings and your class lists, never the model files. After a restore a model shows
**Missing** and its pipelines say **Import the model Gate people again.** Import the same file: the model comes back with
its settings.
