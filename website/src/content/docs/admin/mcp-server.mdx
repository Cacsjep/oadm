An AI agent such as Claude Code or VS Code connects to OADM over MCP and works like a user: it looks at your devices,
checks their health and runs tasks on many devices. It signs in with an **access key**. Each key has its own role and
devices, so you decide what each agent may do. The agent never sees a password.

The MCP server is part of the OADM server. It is off until an administrator turns it on.

<Image src={settings} alt="The page MCP & Assistant, card MCP: port, Listen on, the certificate, the status Running on port 5082, Connect an agent and the access keys" class="screen" />

## Turn it on

<Steps>

1. Open the page **MCP & Assistant** in the rail, the card **MCP**.
2. Choose the **Port** (default 5082) and **Listen on**, the interface the agents reach the server on.
3. Click **Turn on**. The status next to the buttons shows **Running on port 5082**.

</Steps>

Agents connect over HTTPS. The certificate comes from the **MCP server** policy of the [PKI](../../tools/pki/) page, and the
first **Turn on** makes its own certificate, **MCP Server Certificate**. It also names `localhost`, for an agent on the
server's own computer. You can choose another one in that policy. When
PKI is not running, the card says "PKI is not running. The server log says why." On Windows the installed server opens
the port in the firewall while the MCP server is on. On Linux and macOS open it yourself if a firewall runs.

**Turn off** closes the port. Agents can no longer connect.

## Create an access key

Only administrators create and delete access keys.

<Steps>

1. On the page **MCP & Assistant**, card **MCP**, click **Access keys**, then **Create access key**.
2. Enter a **Name** for the agent (letters, digits, spaces, `-`, `_` and `.`).
3. Choose the **Role**. The role decides what the agent may do: a role like Viewer gives an agent that only looks.
4. Choose the **Devices**: **All devices** or one [device group](../device-groups/). A key with the
   Administrator role always has all devices.
5. Choose when it **Expires** (30, 90 or 365 days) and click **Create**.
6. Click the copy button next to the new key and keep it where the agent can read it.

</Steps>

<Image src={accessKeys} alt="The Create access key dialog after Create: the new key, shown once with its copy button" class="screen" />

OADM shows the key once and cannot show it again. Lost it? Delete it and create a new one.

The list under **Access keys** shows each key with its role, devices, when it was created, when it expires and when it
was last used. **Delete** asks first and ends the key at once.

A key is not a login of the person who made it. It keeps working when that person changes. A change of its role or of
its device group applies to the agent's next call.

A key ends when you delete it or on its expiry date. Restoring a backup ends every key. A role or device group that a
key uses cannot be deleted: delete the key first.

## Set up a desktop app

On the MCP card, an administrator can choose **Set up a desktop app** to create a key with a role, device scope and
expiry. Install the packaged `OADM.mcpb` extension in Claude Desktop. Enter the MCP HTTPS address and the access key.
Download the OADM CA certificate from the MCP card if the desktop app needs it. To disconnect, delete the key in OADM
and remove the extension in Claude Desktop.

## Connect an agent

While the MCP server runs, choose your agent under **Connect an agent** and click **Copy**. You get it with this
server's address:

- **Claude Code**: the `claude mcp add` command for a terminal.
- **.mcp.json**: the file for a project folder.
- **VS Code**: the file `.vscode/mcp.json`. VS Code asks for the key when it connects.

Claude Desktop is not listed until a bridge is tested with this server.

Put your key in the variable `OADM_KEY` on the agent's computer before you start Claude Code, for example
`export OADM_KEY=oadm_...`.

The agent's computer must trust your CA once. Click **Download CA certificate** on the card. Claude Code reads the file
named in the variable `NODE_EXTRA_CA_CERTS`. For other agents add the file to the computer's trusted certificates.

## The skill

The skill `oadm` tells an agent how to work with OADM: look at a summary first, narrow the devices with filters, show
you the plan and the skipped devices before it runs anything, and never ask for passwords. It also has a workflow each for
an AXIS OS rollout, a network change, Configure devices, certificates, a health check, one device's troubles,
vulnerabilities, failed tasks, event rules, applications, SD cards and sites.

The server hands the skill to agents that support it. For an agent that does not, click **Download skill** on the card
and put the folder `oadm` from the ZIP file where your agent reads its skills.

## What agents can do

Every tool with what it does: [MCP tools](./tools/).

- Look at devices: counts by status, model, AXIS OS version, site or tag, lists with filters, the details of one
  device, one picture of a camera. What the device list shows needs no call to the device: the clock, the certificate,
  the chip and the vulnerabilities are filters and counts.
- See which devices the published Axis CVEs affect, worst first, with the possible ones apart.
- Read tasks and their results, failures grouped by their error, the server log, the audit log and the event log.
- Read OADM's own state: OADM PRO, which plugins are on, MCP and the assistant, the date of the vulnerability list.
- Run tasks on many devices, such as restart, date and time, Upgrade AXIS OS, network settings, users, applications, their
  settings and license keys, certificates and CA certificates, Configure devices, Import and Export configuration, the SD card tasks of Edge storage and the
  action rules of the Action Rule Editor. An application can come as a vendor's ZIP with several builds: the agent uploads
  it as it is, and each camera gets the build that fits it (see [Applications](../../tasks/applications/#several-files-of-one-application)).
  A task shows in the Tasks list like any other. Its owner is "MCP" and the key's name, for example
  "MCP Lobby-bot". Cancel tasks.
- Refresh, remove and add devices with Discovery, a network range or a list of up to 1,000 addresses, and set their
  login from the credential list by its name, or with a user and password you type. Set the first password of devices
  with factory default settings, and add and remove entries of the credential list. Agents add only addresses in the networks of the server or a site, at most
  200 devices at a time. Read the waiting list and remove entries from it.
- Add, remove, rename, recolor and delete tags, and rename sites.
- Delete tasks from the task history, or all of them, and read what a task's dialog reads from a device, such as its
  users or network settings.
- Create, change, delete, turn on or off, duplicate and test event rules, clear the event log, and create, change, test
  and delete recipients.
- Read which devices fail a compliance check, turn Compliance on or off, create, change, turn off and delete checks, and
  check now.
- Zoom, focus and move a PTZ camera to home, a preset or a point, save its position to a preset, and set the RTSP port
  OADM uses.
- Fetch the vulnerability list now, check for a new OADM version and install it (an Administrator key).
- With an Administrator key: import or remove the OADM PRO license, start the trial, set plugin licenses, turn plugins on
  or off, install and remove optional plugins from their ZIP, set the automatic backups, back up now, download, delete and
  restore backups, and create the support report. A license key or backup password is typed into your own terminal.
- Read a setting, the action rules or the stream profiles of many devices, such as which cameras have capture frequency
  50 Hz.
- Read PKI certificates and create one, and read the EST and 802.1X servers, the NTP server, DHCP server and Hardening
  scan pages, device triggers, text readers and vision pipelines, and as they were last read the SD cards of Edge
  storage, the applications of the Applications page and the action rules of the Action Rule Editor.
  Other plugins can bring their own tools, shown only while the plugin is on.
- Read what the monitoring and maintenance pages show: SD cards, the recordings of a camera, image health, the inputs and
  outputs of a device, open event streams, dashboard values, load test results and snapshot tiles. Also the recipients of
  the event rules and whether they are connected.
- Do on the plugin pages what you can: start a hardening scan, Check now on Image health, read the SD cards, the
  applications or the action rules of chosen devices, save and delete device triggers, dashboards, text readers, vision
  pipelines, saved views and saved commands, press a dashboard button, start a load test, add a static DHCP lease or
  release one, change the recipients and schedules on the devices. Each needs the same permission as on the page. Live
  video stays in OADM.
- Run commands of the [VAPIX Commander](../../tools/vapix-commander/) library and saved commands on many devices, for settings
  no task covers (siren and light, PTZ and more). Not offered: dangerous commands, commands with a file, and changes
  OADM's own tasks make. A value that looks like a password in an answer shows as `***`.
- Send a VAPIX request of their own to the devices of a filter, with the VAPIX Commander permission Send to one device.
  A change runs on one device first and on more only after it worked there. A request that can lock OADM out or break a
  device (accounts, network, HTTPS, 802.1X, AXIS OS, factory default) also needs Send dangerous requests; a restart does
  not. No password goes into a request.
- Change the server settings an administrator changes in OADM: the Settings page's server fields, MCP, the Assistant
  and its API key, the 30-day OADM PRO trial, the NTP and DHCP servers, the EST and 802.1X servers, PKI's certificate
  authorities and policies, Vision Center models and the graphics card settings. The preview shows each old and new
  value and warns when a change can cut off clients, agents or devices.
- Accept site nodes, bind a site node with its pairing code, move the devices of a site to another one, remove a site.
- Trust the new certificate of a device that shows Certificate changed, after you compared both fingerprints, and delete
  all devices.
- Upload files, such as a firmware file, without the file passing through the agent.
- Fetch files OADM makes: the device list and compliance results as CSV, a task's result, a recording, the snapshot
  report, a certificate, the hardening results, a backup (encrypted with its password) and the backup of a CA key
  (protected with a password you type in your own terminal). The agent gets a one-time download link and saves the file
  from its shell; the file never passes through the agent.
- Set a password, passphrase, PKCS#12 password or license key a change needs without the agent seeing it: the agent gives
  you a command, you run it in your own terminal and type the value there. It goes straight to OADM and is used once.
  OADM checks it at once; a value it refuses (too short, a wrong PKCS#12 password) is answered in your terminal.
- With an Administrator key: add, change, disable and delete users and set their passwords, create, change and delete
  roles and device groups, and create and delete access keys, as an administrator can on the Permissions page. The plan
  says it in words when someone gets more rights, such as "anna becomes Administrator". The last administrator and the
  agent's own key stay. A new key is never shown to the agent: it gives you a command that saves the key to
  `oadm-key.txt`, once. A key an agent creates ends no later than the agent's own key.

Every change has two steps. The agent asks OADM for a **preview** that checks everything and writes nothing. It answers
what would run, on which devices, what is skipped and why, and any warning. Only after you agree does the agent run it,
and the run can only do what the preview showed.

A key with a device group gets only the devices of the group. A role without a permission does not get the tools for
it. The audit log names the key: "MCP Lobby-bot".

## What agents cannot do

- Read passwords, private keys, license keys or tokens, or get one through the chat. A password you type into the
  agent's command goes to OADM only.
- Change users, roles, device groups or access keys with a key of any role other than Administrator, or delete its own
  key.
- Show live video, pan and tilt a camera continuously, or import devices from an ADM file with their logins.
- Do more than the role and devices of their key.

Texts that come from devices, such as names, locations and log lines, are data for the agent, never orders.

## Limits

A key can make 20 calls a second, 10 changes and 30 camera pictures a minute. A key has at most 4 calls waiting for an
answer. A list answers at most 200 rows at a time, with the total; a log says whether more lines follow instead. No
answer is larger than 32 KB. An agent asks for a summary first and narrows with filters.

## Troubleshooting

| What you see | What to do |
|---|---|
| **PKI is not running. The server log says why.** | Open the Logs page and look for the PKI error. |
| **Port 5082 cannot be opened** | Another program uses the port. Choose another port and save. |
| The agent says **The access key is not valid. An administrator creates a new one in OADM on the page MCP & Assistant.** | The key is wrong, deleted or has ended. Create a new one. |
| The agent does not trust the server | Trust the CA once: **Download CA certificate** on the card. |
| The agent has no tool for something | The key's role does not have the permission, or the plugin is off. Check the role on the Permissions page. |
| **The access key Lobby-bot has the role Agents. Delete the key first.** | A key uses the role or device group you want to delete. Delete the key first. |
| **Too many calls with this access key. Wait a second.** | The agent waits a second and tries again. |
| **Too many calls at once. Wait for an answer.** | The agent waits for its other calls to answer. |
| **Too many changes with this access key. Wait a minute.** | The agent made 10 changes in a minute. It waits. |
| **Too many pictures. Wait a minute.** | The agent took 30 camera pictures in a minute. It waits. |
