Each topic is a card that folds. The cards start closed: click a card's title to open it. A card opens by itself when a
field in it shows an error.

## Client

The first card is for the computer you sit at. Every user can change it, and it is saved at once.

| Setting | Default | What it does |
|---|---|---|
| Decode video on the graphics card | On | Live video is decoded by the graphics card when it can; the hint below says what the test found. An orange icon over the video says what to do when the processor decodes instead. |
| Show video details over the picture | Off | A card at the top right of the live video with codec, resolution, frame rate, bit rate and decoding. |
| Frame rate (adaptive quality) | 20 | Frames per second when the resolution follows the size of the picture (1 to 30). |
| Appearance | Dark | Dark or Light. Takes effect after the client restarts. |
| Tell me about new versions | On | After the login, says when a newer OADM version is out. |

## Server

Administrators change the server settings; operators see them. They apply to every client of the server. The settings
stand in five cards: Polling, Discovery, Tasks, Security and Server. **Save** below the cards saves all five;
**Reload** reads them again.

| Setting | Default | What it does |
|---|---|---|
| Status polling interval (s) | 60 | How often OADM checks that every device answers. A device that does not answer within 3 s is asked once more before it shows Unreachable. |
| Read device details every (min) | 10 | How often OADM reads network settings and certificates of every device that answers. A new firmware is read at once. |
| Addresses scanned at once | 32 | Speed of **Network range**. |
| Scan timeout (ms) | 1500 | How long **Network range** and imports wait for each address. |
| Discovery duration (s) | 30 | How long **Discovery** on the add page searches (5 to 300). |
| Try waiting devices every (min) | 15 | How often OADM tries the devices of imports that did not answer (1 to 1440). |
| Parallel tasks per plugin | 16 | How many devices a task runs on at the same time, for example restarts or firmware updates. Takes effect at once. |
| Allow Basic login over HTTP | Off | For devices without HTTPS that accept only Basic login. OADM then sends their password unencrypted. Turn on HTTPS on the devices instead when you can. **Disable HTTPS** on such a device runs only while it is on. Takes effect at once. |
| Server name | Computer name | Shown in the login window. |
| Listen URL | `https://0.0.0.0:5080` | Address and port of the server. Takes effect after the server restarts. |

## Backup and restore

Administrators back up the whole server and restore it, also on a new computer. A backup holds the devices with their
logins, users and roles, tags, event rules, settings, the credential list, the task history and the plugins' data (for
example the PKI's certificate authorities). It is one file, encrypted with a password you choose. Without the password
nobody can read it, OADM included.

<Image src={backup} alt="The backup and restore card" class="screen" />

- **Back up now**: enter a password, choose where to save the file.
- **Automatic backups**: every day at the time you choose (server time), the newest ones kept on the server
  (**Backups kept**, 7 by default). They use the password you enter here; a restore needs it. The list below shows them, with
  **Download**, **Restore** and **Delete**.
- **Restore from file** or **Restore** in the list: enter the password and click **Check**. OADM reads the whole backup
  and shows what it holds; nothing changes yet. **Restore** asks once more.

<Image src={restore} alt="The restore dialog after Check" class="screen" />

A restore replaces everything on the server. Before it starts, OADM saves the current state as a backup on the server
(**Before a restore** in the list), cancels running tasks and restarts the server. Everyone logs in again. Afterwards the
card shows what was restored.

A backup of an older OADM is upgraded when it is restored. A backup of a newer OADM is refused: update OADM first.

## License

The **License** card shows this server's OADM PRO license. OADM itself works the same with or without one; PRO adds
commercial support, the EST and 802.1X servers and PRO plugins.

<Image src={license} alt="The License card without a license, with Start 30-day trial" class="screen" />

- **Server ID**: the ID a license is made for. The copy button puts it on the clipboard.
- **OADM PRO**: the plan and the last day, **Trial** and its last day during the 30-day trial, or what is wrong
  (expired, trial ended, made for another server, not valid).
- **Start 30-day trial** (administrators): OADM PRO runs at once for 30 days, no account and no internet needed. Once per
  server. Other users see that an administrator can start it.
- **Activate license** opens [Activate OADM PRO](../../activate/) with the server ID filled in. A bought license code
  gives you the license file (`.oadmlicense`) at once.
- **Import license** (administrators): choose the license file. It applies at once and replaces the trial.
- **Remove license** (administrators): the EST and 802.1X servers and PRO plugins stop on this server, unless the trial
  still runs.

A license moves with a backup: after a restore on a new computer the server keeps its ID and its license. A running trial
does not move to another computer.

## Support

**Create support report** (administrators) saves one ZIP file for a support request: the server's log files, a summary
of the server (versions, system, counts of devices, tasks and plugins, the settings) and the log files of the client you work on.
No passwords or keys are included. The logs name devices by address and serial number, like the Logs page. Attach it to your post in the
[Support Forum](https://support.oadm.app/) or your issue.

## Kept by each client

Each client also keeps its own settings on its computer: the servers you used, the device list columns, group by tag,
the size of the tasks pane, the **Client** card above, and whether the add page uses DNS names.
