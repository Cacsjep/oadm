A **site** is a network the OADM server cannot reach itself: another building, a network behind a router, a camera
network of its own. Install the **OADM Site Node** on one computer in that network. The server then reaches the devices
there through the node, and you work with them like with every other device.

- The node connects to the server. It never listens: nothing at the site needs an open port.
- The node keeps no passwords and no device data. Only the server does.
- One site has one node.

## Install the node

Download the site node from the [latest release](https://github.com/Cacsjep/oadm/releases/latest). A Raspberry Pi 4
or 5 works well as a node.

<Tabs syncKey="os">
<TabItem label="Windows">

<Steps>

1. Download `OADM-SiteNode-<version>-win-x64.msi` and double-click it.
2. Finish. The Windows service **OADM Site Node** starts now and on every boot.
3. Start menu > **OADM Site Node** opens the app. It asks you to accept the terms of use once.

</Steps>

- Silent install with the server's address: `msiexec /i OADM-SiteNode-<version>-win-x64.msi SERVER=oadm.example.com /qn`.
- Data folder: `%ProgramData%\OADM Site Node`. Uninstalling keeps it.

</TabItem>
<TabItem label="Linux">

Debian and Ubuntu (also Raspberry Pi OS), x64 (`amd64`) or ARM64 (`arm64`). Download both `.deb` files of your
computer's type:

```sh
sudo apt install ./oadm-site-node_*.deb ./oadm-site-node-app_*.deb   # service and app
sudo apt install ./oadm-site-node_*.deb                             # service only, no desktop
```

- Service: `oadm-site-node` (`sudo systemctl status oadm-site-node`). It runs as its own user, not as root.
- App: app menu > **OADM Site Node**, or `oadm-site-node-app`.
- Data folder: `/var/lib/oadm-site-node`. Uninstalling keeps it.

</TabItem>
</Tabs>

## Connect the node to the server

<Steps>

1. In OADM, open **Sites** and turn on **Accept site nodes** (administrators).
2. In the node app, enter the server's name or IP address under **Server address** and click **Save**. Port 5081
   unless you enter another one. Windows asks for administrator rights, Linux for your password.
3. Under **Node status** the app says **Connected to** the server. On the **Sites** page the node shows as **Waiting to
   be bound**.

</Steps>

Enter the server's DNS name if it has one. The node also learns the server's other addresses and finds it again when
its address changes.

## Bind the site

<Steps>

1. In the node app, read the **Pairing code** below the server address. A code is valid for 10 minutes; the app shows
   the next one by itself.
2. On the **Sites** page, click **Bind** on the node's row.
3. Enter the **Site name** and the **Pairing code** and click **Bind**.

</Steps>

From now on the node works only with this server. Add devices at the site like any other devices: Discovery, Network
range and Add manually also search through the node. The **Site** column of the device list shows where a device is.

- Binding is open for 24 hours of the node's run time. Then the app says **Binding closed**: click **Allow binding** for
  another 24 hours and a new code.
- After 5 wrong codes the node makes a new code and refuses binding for 10 minutes.
- When the node is offline, its devices show **Site offline**. Nothing is sent to them until it is back.

## Networks

Under **Networks**, **Reach devices on** says where the node looks for devices: **All cards** (default), or the cards
you tick in the list. Tick only the camera cards when the node's computer also sits in an office network. Networks behind a router, e.g. a
camera network `10.20.0.0/16`, are added on the command line: `oadm-site-node networks add 10.20.0.0/16`.

The node never connects to an address outside these networks.

## Ports

The **Ports** table lists the ports the node may use. Ports the server asks for come first, marked **Requested**:
**Allow** or **Dismiss** them. Add a port with **Add port** below the table.

- **Connect to**: the device ports the node may connect to. TCP 80, 443 and 554 by default.
- **Listen on**: ports the node opens at the site for the server, e.g. UDP 123 when the [NTP server](../../tools/ntp-server/)
  serves the cameras there. Empty by default.

When the server needs another port, e.g. a camera on TCP 8443, the app lists it with the reason. Click **Allow** or
**Dismiss**.

## Manage sites

On the **Sites** page (administrators):

- **Rename**: a new name for the site. The node app shows it too.
- **Replace with**: moves the devices of a site to another site that is online. Each device must answer there first;
  devices that do not stay where they are.
- **Remove site**: with **Keep devices** checked, the devices stay and show **Site offline**. Later **Replace with**
  moves them to another site, or **Remove devices** removes them. Unchecked, the devices are removed with their logins
  and tags. The node forgets the server; when it is offline, click **Reset** in the node app.
- **Turn off site nodes**: the server stops accepting nodes and disconnects the connected ones. Their devices show
  **Site offline** until you turn on **Accept site nodes** again. Sites and devices stay.

## Reset the node

**Reset** in the node app: the node tells the server, forgets it and gets a new identity and pairing code. The old site
shows **Not bound** on the **Sites** page and its devices **Site offline**. The node connects again and waits to be
bound.

<Steps>

1. Click **Bind** on the node's row. The name starts as the node's name, with "(2)" when the old site has it. Enter
   the pairing code.
2. On the old site's row, click **Replace with** and choose the new site. Its devices move.
3. Or click **Remove site** on the old site's row instead.

</Steps>

When the node cannot reach the server at Reset, the old site shows **Offline** instead.

## New server identity

The server proves itself to its nodes with a key of its own. When the server's key is replaced (the warning "The
server's key was replaced" in OADM), the nodes no longer know the server and its sites show **Offline**.

<Steps>

1. In the node app, check the server and the fingerprint the app shows, then click **Accept new server identity**
   (administrator rights). The pairing code appears.
2. On the **Sites** page the node waits to be bound again. Click **Bind**: the site keeps its name. Enter the pairing
   code.

</Steps>

The site and its devices stay as they were. Accept alone binds nothing: only the pairing code does.

## Without a desktop

On a computer without a desktop, use the command line. Changes need administrator rights (`sudo` on Linux).

| Command | Does |
|---|---|
| `oadm-site-node status` | State, server, connections |
| `oadm-site-node pairing-code` | The pairing code |
| `oadm-site-node server oadm.example.com` | Connect to this server; shows the pairing code while not bound |
| `oadm-site-node allow-binding` | Binding open for another 24 hours, a new code |
| `oadm-site-node networks` | Network cards and extra networks; `card <name> on\|off`, `all on`, `add`, `remove` change them |
| `oadm-site-node ports` | Allowed and requested ports; `allow`, `remove`, `dismiss` change them |
| `oadm-site-node log` | The newest connections through the node |
| `oadm-site-node reset` | Forget the server, new identity and code |

## Good to know

- **Server port**: the server accepts site nodes on TCP 5081, only while **Accept site nodes** is on. On Windows the
  server opens it for Domain and Private networks while it is on.
- **Many live connections**: every lasting connection through a node (device events, live video, the web interface)
  uses one outgoing port of the node's computer. Windows has 16,384 of them by default, Linux about 28,000. For more,
  widen the range: on Windows `netsh int ipv4 set dynamicport tcp start=10000 num=55535`, on Linux the setting
  `net.ipv4.ip_local_port_range`.
- **Encryption**: devices reached over HTTPS stay encrypted all the way. Devices on plain HTTP or plain RTSP can be read
  on the node's computer, like on the network itself.
- **Connection log**: the node keeps the last connections through it in its data folder for 30 days;
  `oadm-site-node log` shows the newest.
