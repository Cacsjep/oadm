The **Plugins** page lists the plugins you can turn off, each with a short description. Only administrators see it.

Turn a plugin on or off with its check box. The server applies the change at once, without a restart, and writes it to
the audit log. A plugin that is off shows no page, menu entry or toolbar button, and the server does not run it. Other
clients see the change the next time they connect.

| Plugin | Default |
|---|---|
| VAPIX Commander, NTP server, DHCP server, Web View | On |
| Action Rule Editor, Applications, Dashboards, Device triggers, Edge Recording Export, Edge storage, Hardening scan, Image Health Dashboard, Load test, I/O Monitor, Live View, Metadata Monitor, Snapshot report | Off |

Restart, Upgrade AXIS OS, Date and time, Device configuration, Applications (ACAP), Users, Network settings, PKI,
System report, Outputs and Notifications are the everyday device work. They are always on and not listed. The
[EST server](../../tools/est-server/) and the [802.1X server](../../tools/radius-server/) are part of PKI: you turn each on
with **Turn on** on its tab of the PKI page; they need OADM PRO.

## Optional plugins

Some plugins of OADM are not in its installers because they are large. The **Optional plugins** card below the list
shows the ones of your OADM version.

- **Install** downloads the plugin from the OADM release on GitHub, checks it and adds it without a restart. It starts
  off: turn it on in the list above.
- **Remove** turns it off at once. Its files go at the next restart of the server; its settings are kept for a new
  install.
- When you update OADM, the server downloads the optional plugins of the new version by itself. A plugin it cannot
  download stays off and its row says so; click **Install** to try again.
- The clients get the plugin from the server. Nothing is installed on their computers.
- The server needs to reach github.com. Without it, download the plugin's ZIP for your server's system
  (`oadm-addon-<id>-<version>-<system>.zip`) from the release page and unpack it into the folder `addons/<id>` in the
  server's data folder (`%ProgramData%\OADM`, `/var/lib/oadm` or `/Library/Application Support/OADM`), then restart the
  server.

Install and Remove are written to the audit log.

## OADM PRO plugins

Plugins that need OADM PRO are listed for everyone. Their License column shows **OADM PRO**:

- While an OADM PRO license or trial is active, the chip is green and you turn the plugin on or off like any other.
- Without one, the check box is locked and **Activate** (administrators) opens Settings with the **License** card, where
  you start the 30-day trial or import a license.
- When the license ends or is removed, the PRO plugins stop at once. Your choice is kept: with a new license they run
  again.

## Licenses

Some plugins from others are sold with a license. They show a **License** column with their state: Licensed, Trial, Trial
ended, No license, Expired, Other server or Not valid; the tooltip says why.

1. Copy the **Server ID** at the top of the page or in Settings > License (copy button) and send it to the plugin's vendor.
2. You get a license key back, one line starting with `OADM1.`, or a file with it. Click **Enter license** in the plugin's
   row, paste the key or click **Choose file**, then **Save**. Below the field OADM shows whom the key is for. A key for
   another server, an expired one or a changed one is refused with the reason.
3. **Change license** replaces it, **Remove** takes it away.

The server ID stays the same when you restore a backup on another computer, so a moved server keeps its licenses. Entering
and removing a license is written to the audit log.

## Plugins from others

You can add plugins that do not come with OADM. A plugin comes as a `.oadmplugin` file (a ZIP) or as a folder named
like the plugin, for example `acme.site-reports`:

1. Unpack it into a folder with the plugin's name in the server's plugin folder:

   | System | Folder |
   |---|---|
   | Windows | `%ProgramData%\OADM\plugins` |
   | Linux | `/var/lib/oadm/plugins` |
   | macOS | `/Library/Application Support/OADM/plugins` |

2. When the plugin has a dialog or a page, unpack it on every computer with the client too, into
   `%LOCALAPPDATA%\Oadm\plugins` (Windows), `~/.local/share/Oadm/plugins` (Linux) or
   `~/Library/Application Support/Oadm/plugins` (macOS).
3. Restart the OADM server service and the clients. The plugin is listed on this page; turn it on if it is off.

Install only plugins you trust, as you would any program on the server:

- A plugin runs inside the OADM server with the server's rights: as the installed service that is Local System on
  Windows and root on Linux and macOS. It can reach the network, the files of the server and every device OADM manages,
  logged in with the stored passwords (it never sees the passwords themselves).
- **Off** on this page stops what the plugin runs and hides it, but its code stays loaded until the server restarts.
  To remove a plugin, delete its folder and restart the server and the clients.
- As a service, OADM makes every plugin folder writable only by administrators when it starts. A folder it cannot fix
  is not loaded, and the server log names it.
- Plugins that come with OADM are reviewed and tested with every release. For one from somewhere else, ask for its
  source and who checked it.
