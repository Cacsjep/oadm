The **Plugins** page lists the plugins you can turn off, each with a short description. Only administrators see it.

Turn a plugin on or off with its check box. The server applies the change at once, without a restart, and writes it to
the audit log. A plugin that is off shows no page, menu entry or toolbar button, and the server does not run it. Other
clients see the change the next time they connect.

| Plugin | Default |
|---|---|
| VAPIX Commander, NTP server, DHCP server, Web View | On |
| Action Rule Editor, Applications, Dashboards, Device triggers, Edge Recording Export, Edge storage, Hardening scan, Image Health Dashboard, Load test, I/O Monitor, Live View, Metadata Monitor, Snapshot report | Off |
| Text recognition (an [optional plugin](#optional-plugins), installed first) | Off |

Restart, Upgrade AXIS OS, Date and time, Device configuration, Applications (ACAP), Users, Network settings, PKI,
System report, Outputs, Notifications, Modbus, MQTT and OPC UA are the everyday device work. They are always on and not listed. The
[EST server](../../tools/est-server/) and the [802.1X server](../../tools/radius-server/) are part of PKI: you turn each on
with **Turn on** on its tab of the PKI page; they need OADM PRO.

## Optional plugins

Some plugins of OADM are not in its installers because they are large. The **Optional plugins** card below the list
shows the ones of your OADM version with their state: **Not installed**, **Installing 42 %**, **Up to date**, **Update available** or **Removed**.

| Optional plugin | What it does |
|---|---|
| [Text recognition](../../tools/text-recognition/) | Reads text in camera pictures |

### Install

<Steps>

1. Click **Download ZIP** in the plugin's row. It opens the ZIP of your server's version and system in the browser. For a
   server without internet, download it on another computer: the tooltip names the file, and the
   [OADM releases](https://github.com/Cacsjep/oadm/releases) list it as `oadm-addon-<id>-<version>-<system>.zip`.
2. Click **Install** and choose the ZIP on this computer. The row shows **Upload**, **Check** and **Install** with their
   progress. **Cancel** stops the upload.
3. When the row says **Up to date**, turn the plugin on in the list above. It starts off.

</Steps>

The server takes only the genuine ZIP of its own version and system, so a changed or wrong file never runs on the server.

No restart is needed. The clients get the plugin from the server, also clients that are connected now. Nothing is
installed on their computers and they need no rights for it. A client that runs while the server gets a new version
of a plugin says **Restart the client to use the new version.**

Only administrators install and remove optional plugins. Both are written to the audit log, for example
`Installed optional plugin Text recognition V4.10.0`.

### Install by hand

A build you made yourself cannot check the ZIP, so **Install** stays off. Unpack the ZIP into `addons/<id>` of the data
folder and restart the server. A folder loads when it is of this OADM version or an older one.

### Remove

**Remove** asks **Remove Text recognition? It turns off now. Its settings are kept.** The plugin turns off at once and
the row says **Removed**: its files go at the next restart of the server. Its settings and readers stay. Until the
restart, **Install** brings it back at once, without a file.

### Updates and backups

After you update OADM, an optional plugin keeps running. Its row tells you what to do, whatever version number it shows:

| Row | What it means |
|---|---|
| **Up to date** | This OADM has nothing newer for the plugin |
| **Update available** | Click **Download ZIP** and **Install** |
| **Restart needed** | The new version starts when the server restarts: click **Restart server**, or restart it later. Not while a task runs |
| **Not loaded. Install it again for this OADM version.** | The plugin cannot run on this OADM: click **Download ZIP** and **Install** |

Administrators also get a dialog after they sign in when a plugin needs an update. Your choice of on or off and your settings
are kept.

A backup holds the list of installed optional plugins, not their files. After a restore on another computer the row says **Not loaded**:
install the plugin again.

### Messages

| Message | Do this |
|---|---|
| **This file is not the ZIP of this OADM version and system. Download it again.** | Use **Download ZIP** in the row. A file that is damaged or changed is refused too |
| **This ZIP is for another OADM version. This server needs V4.10.0.** | Use **Download ZIP** in the row |
| **This ZIP is for another system. This server needs win-x64.** | Use **Download ZIP** in the row. The system of the server counts, not that of your computer |
| **This ZIP holds another plugin. Choose the ZIP of Text recognition.** | Choose the ZIP of the plugin in this row |
| **The file is damaged. Download it again.** | Use **Download ZIP** in the row |
| **The upload stopped. Try again.** | Check the connection to the server and click **Install** again |
| **This OADM build cannot check optional plugins. Put the plugin into its folder by hand.** | A build you made yourself. Install a release of OADM, or [install by hand](#install-by-hand) |
| **Not enough free disk space for the optional plugin.** | Free space on the drive of the data folder |
| **The server is updating.** | Wait until the update is done |
| **An optional plugin is being installed or removed. Try again when it is done.** | Wait, one install or remove runs at a time |

## OADM PRO plugins

Plugins that need OADM PRO are listed for everyone. Their License column shows **OADM PRO**:

- While an OADM PRO license or trial is active, the chip is green and you turn the plugin on or off like any other.
- Without one, the check box is locked and **Activate** (administrators) opens Settings with the **License** card, where
  you start the 30-day trial or import a license.
- When the license ends or is removed, the PRO plugins stop at once. Your choice is kept: with a new license they run
  again.

## Licenses

Some plugins from others are sold with a license. They show a **License** column with their state: Licensed, Trial, Trial
ended, No license, Expired, Other server or Not valid; the tooltip says why.

1. Copy the **Server ID** at the top of the page or in Settings > License (copy button) and send it to the plugin's vendor.
2. You get a license key back, one line starting with `OADM1.`, or a file with it. Click **Enter license** in the plugin's
   row, paste the key or click **Choose file**, then **Save**. Below the field OADM shows whom the key is for. A key for
   another server, an expired one or a changed one is refused with the reason.
3. **Change license** replaces it, **Remove** takes it away.

The server ID stays the same when you restore a backup on another computer, so a moved server keeps its licenses. Entering
and removing a license is written to the audit log.

## Plugins from others

You can add plugins that do not come with OADM. A plugin comes as a `.oadmplugin` file (a ZIP) or as a folder named
like the plugin, for example `acme.site-reports`:

1. Unpack it into a folder with the plugin's name in the server's plugin folder:

   | System | Folder |
   |---|---|
   | Windows | `%ProgramData%\OADM\plugins` |
   | Linux | `/var/lib/oadm/plugins` |
   | macOS | `/Library/Application Support/OADM/plugins` |

   Do this as an administrator (Linux and macOS: with `sudo`), and copy or unpack the plugin there. A folder you move
   there still belongs to your user, and OADM [does not load it](#plugin-folders-other-users-could-change).

2. When the plugin has a dialog or a page, unpack it on every computer with the client too, into
   `%LOCALAPPDATA%\Oadm\plugins` (Windows), `~/.local/share/Oadm/plugins` (Linux) or
   `~/Library/Application Support/Oadm/plugins` (macOS).
3. Restart the OADM server service and the clients. The plugin is listed on this page; turn it on if it is off.

Install only plugins you trust, as you would any program on the server:

- A plugin runs inside the OADM server with the server's rights: as the installed service that is Local System on
  Windows and root on Linux and macOS. It can reach the network, the files of the server and every device OADM manages,
  logged in with the stored passwords (it never sees the passwords themselves).
- **Off** on this page stops what the plugin runs and hides it, but its code stays loaded until the server restarts.
  To remove a plugin, delete its folder and restart the server and the clients.
- Plugins that come with OADM are reviewed and tested with every release. For one from somewhere else, ask for its
  source and who checked it.

### Plugin folders other users could change

As a service, OADM loads a plugin folder only when nobody but administrators could change it. It checks this at every
start.

- A plugin folder that other users could change is not loaded. OADM makes it writable only by administrators and moves
  it to `plugins-not-loaded-<time>` next to the `plugins` folder. The server log names it. The other plugins load as
  usual.
- When other users could change the `plugins` folder itself or the folder above it, OADM moves the whole `plugins`
  folder there: anyone could have put a plugin into it.

Check the plugin, move its folder back into `plugins` and restart the OADM server service. It loads then.
