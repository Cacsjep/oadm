The context menu group **Security** holds the certificate tasks. Most of them use the policies and CAs of the
[PKI](../../tools/pki/) page: OADM signs the device certificates itself, and devices with such a certificate show as
**Trusted** in the device list.

<Aside>
Every certificate task needs AXIS OS 6.53 or later. Other devices show the entries greyed with the reason.
</Aside>

## Supported AXIS OS

| AXIS OS | HTTPS | IEEE 802.1X | Keys |
|---|---|---|---|
| 12.x | Yes | Yes, EAPOL version 1, 2 or 3 | ECC or RSA |
| 10.1 to 11.11 | Yes | Yes, EAPOL version 1, 2 or 3 | RSA |
| 6.53 to 10.0 | Yes | Yes, EAPOL version 1 or 2 | RSA |

On AXIS OS before 12, choose policies with an RSA key. Before 10.1, choose an IEEE 802.1X policy with EAPOL version 1
or 2. A new server's built-in policies use ECC and EAPOL version 2: add a policy with RSA for older devices on the PKI
page. A device that cannot use the chosen policy is not changed. Enrollment on the [EST server](../../tools/est-server/)
needs AXIS OS 12.10 or later.

## Enable or disable HTTPS

**Enable HTTPS** gives each device its own HTTPS certificate. The dialog shows the **Policy** (an HTTPS certificate policy
of the [PKI](../../tools/pki/) page, the first one is chosen) and below it what the policy issues: the CA, the days and
the key. To change these values, change the policy or choose another one. Then:

1. The device creates a key of the policy's kind (ECC or RSA). The private key never leaves the device. A device that
   cannot create that key is not changed.
2. OADM signs the request with the policy's CA, with the device's IP addresses and host names.
3. OADM installs the certificate, switches the web server to it (HTTP only becomes HTTP and HTTPS) and connects again
   over HTTPS.
4. Older OADM certificates that nothing uses any more are removed.

**Disable HTTPS** sets the device to HTTP only. It asks first: video systems that use HTTPS lose the connection. The
certificates stay on the device. A device that accepts only Basic login over HTTP is changed only while **Allow Basic
login over HTTP** is on in Settings > Security.

Both tasks wait up to 1 minute for the device's web server to restart before they check the new connection. Renew
certificates and Install certificates for HTTPS wait the same way.

## Enable or disable IEEE 802.1X

<Image src={enableShot} alt="The Enable IEEE 802.1X dialog with the policy and what it issues" class="screen" />

**Enable IEEE 802.1X** installs the RADIUS server CA and the CA of the policy, issues a client certificate and turns on
802.1X with that certificate. The dialog shows the **Policy** (an IEEE 802.1X certificate policy) and what it does: the
CA, days and key, the EAP identity the camera signs in with and the CA it checks the RADIUS server with.

<Aside type="danger">
Devices on switch ports that enforce 802.1X become unreachable if authentication fails. The dialog says so above the
policy. OADM always installs the policy's RADIUS server CA and does not check it against your RADIUS server: turn 802.1X
off on the switch ports first, or try one device.
</Aside>

**Disable IEEE 802.1X** turns 802.1X off. The certificates stay.

## Renew certificates

<Image src={renewShot} alt="The Renew certificates dialog with the IEEE 802.1X policy" class="screen" />

**Renew certificates** renews the HTTPS and IEEE 802.1X certificates that OADM issued, with a new key. HTTPS uses the
first HTTPS certificate policy. For IEEE 802.1X the dialog asks for the **IEEE 802.1X policy**: the renewal sets its EAP
identity, EAPOL version and RADIUS server CA on the camera, so choose the policy the cameras were set up with. A use
without an OADM certificate is skipped, for example "No OADM HTTPS certificate on this device".

## The camera's clock

Every certificate starts 5 minutes in the past, so small differences do not matter. Before Enable HTTPS, Enable IEEE
802.1X and Renew certificates start, the dialog reads the camera clocks. When a camera is further behind, it asks, for
example "The camera's time is 9 min 12 s behind. The certificate becomes valid on the camera only in 4 min 12 s. Set the
camera to use NTP. Continue?" With **No** nothing starts. Set the time first with
[Date and time](../date-and-time/).

## View and delete certificates

**View certificates** lists the certificates of the selected devices, grouped as client, server and CA certificates:
name, issued by, issued to, valid to, in use and source (OADM or other). It reads up to 4 devices at a time and changes
nothing. Choose at most 5,000 devices.

**Delete certificates** shows the same list with check boxes. Certificates in use and the Axis factory certificates
are greyed and cannot be deleted. When OADM cannot read what a device uses its certificates for, In use says
**Unknown** and nothing on that device can be deleted. Choose the certificates, click **Delete certificates** and confirm.

## Install certificates

**Install certificates** installs your own `.pfx` or `.p12` files.

<Steps>

1. Choose **Use for**: **HTTPS (server certificate)**, **IEEE 802.1X (client certificate)** or **CA certificates
   only**. For IEEE 802.1X also choose the **Policy**: its EAP identity, EAPOL version and RADIUS server CA go to the
   devices with the file. For **CA certificates only** the file must hold CA certificates only.
2. Click **Choose files** and enter their password.
3. Each file goes to the selected device whose MAC address, IP address or host name it names. The table shows the
   match and any problem.
4. Click **Install** and confirm.

</Steps>

A device without a matching file ends with a warning and nothing is sent.

## Install CA certificates

**Install CA certificates** installs one or more CA certificates on many devices, for example of a RADIUS server or a
video management system. It does not need the OADM CA.

<Image src={shot} alt="The Install CA certificates dialog with three certificates" class="screen" />

<Steps>

1. Click **Add files**. PEM and DER files work, also files with several certificates.
2. The table lists each certificate once. A row with a problem says why, for example "Not a CA certificate" or
   "Expired", and is left out.
3. Click **Install** and confirm.

</Steps>

Certificates a device already has are skipped. At most 150 certificates per run.

## Certificate enrollment

With OADM PRO, **Certificate enrollment** sets the cameras up for the [EST server](../../tools/est-server/), so they renew
their certificates by themselves.

## What OADM checks first

- The device has AXIS OS 6.53 or later, read fresh from the device, and can make the policy's key and use its EAPOL
  version.
- The chosen policy still exists and its CA can issue.
- A device whose certificate changed is refused; remove it and add it again once you know why the certificate
  changed.
- The CA certificates are valid CA certificates and not expired.
- For deleting: the certificate exists, is not in use and is not a factory certificate.

A failed check ends with "Nothing was changed".
