**Upgrade AXIS OS** installs AXIS OS, the firmware of Axis devices, on the selected devices: a version from axis.com or a file you chose. OADM sends it
to each device, waits for the restart, checks the new version and commits it. It is in the context menu under **Maintenance** and in the toolbar.

<Image src={shot} alt="The Upgrade AXIS OS dialog with a version per device and the options below" class="screen" />

## Run it

<Steps>

1. Select the devices, right-click and choose **Maintenance** > **Upgrade AXIS OS**.
2. In the device table, the **Version** of each device is a version from axis.com or **Choose file** for a file of your
   own. **Set versions** at the top right of the table sets every device at once. Keep the original file name, for example
   `P3265-V_12_11_77.bin`: OADM reads the product and version from it. A file chosen for one device is set for every device
   of that model; change single devices afterwards if needed.
3. Check the **Result** column. It says per device what will happen, for example **Upgrade**,
   **Up to date**, **No file**, **Wrong product** or **Downgrade blocked**.
4. Choose the **Factory default** option and, if needed, **Allow downgrade (requires a factory default)**.
5. Click **Upgrade**. Chosen files are uploaded to the OADM server once, versions from axis.com are downloaded by the
   server, then a task starts per device.

</Steps>

Devices that are already up to date, have no file for their model or are refused get no task.

## Versions from axis.com

OADM lists the AXIS OS versions axis.com offers for the model of each device, grouped as on axis.com: the active track (for example
"AXIS OS 13"), "LTS 2026 · 12.11", "LTS 2024 · 11.11" and older ones. **Set versions** at the top right of the table sets every device; choosing in one device's **Version** changes only
that device:

| Set versions | Version |
|---|---|
| Recommended | The newest version of the line the devices run now: 11.11 stays on 11.11. |
| Latest LTS | The newest LTS version of the model. |
| Latest active | The newest version of the active track, or the newest version when the model has none. |

Downloads from axis.com need your MyAxis account. Click **Sign in to MyAxis to download AXIS OS** in the dialog, or the cloud button in the title bar. Signed
in, the dialog opens with **Recommended**. Not signed in, every device starts on **Choose file** and the versions show for
information. Each user signs in with their own account; the server downloads with the account of the user who starts the
upgrade, checks the file against the checksum on axis.com and keeps it 7 days for the next run.

A model axis.com does not list (for example P12-MkIII) offers **Choose file** only. When axis.com cannot be reached, the
dialog says so and every device keeps **Choose file**.

## Options

| Factory default | What happens |
|---|---|
| None, keep all settings (recommended) | Settings stay. OADM commits the new version after it verified it. |
| Soft, reset settings but keep network settings | Settings, users and passwords are reset. The IP address stays. OADM loses access until a new password is set. |
| Hard, reset everything including the IP address | Everything is reset. A device with a static address falls back to DHCP or 192.168.0.90. |

A downgrade always needs a factory default. The device decides itself if it accepts the older version.

## What OADM checks first

- The device status is OK and the device supports AXIS OS upgrades.
- The file ends in `.bin` and is between 1 MB and 2 GB. The device checks product and signature itself and refuses a
  wrong file before it installs anything.
- The product in the file name matches the device.
- The same version is not installed again.
- No earlier upgrade is waiting to be committed.

A refused device fails with "Nothing was changed". The other devices continue.

## Upgrade path

Axis recommends not to jump over an LTS version (for example 11.11 or 10.12), and to leave an LTS version from its latest
release. AXIS OS 12.6.85, 11.11.169 and later refuse other upgrades. When a device jumps over an LTS version, its row says
**Not recommended** and **Details** names what to install first, for example "Recommended path: the latest AXIS OS 11.11,
then 12.6.85." When a device leaves its LTS version, **Details** says "Major upgrade. Make sure the device runs the latest
AXIS OS 12.11 first." The upgrade still starts; if the device refuses it, the task ends with the same text. A factory
default does not need the path.

## AXIS OS 13

AXIS OS 13 has breaking changes. When a device moves up to it, the dialog shows a link to the Axis guide. Read it before
upgrading.

A device refuses AXIS OS 13 while an installed application is unsigned or does not support AXIS OS 13. The dialog reads
the applications of each device: such a device shows **Apps block it**, **Details** names the applications, and the device
gets no task. Update or remove them with **Applications (ACAP)** and try again. Applications that come with AXIS OS do not
count.

## Steps

Check compatibility, Read device info, Validate file, Download AXIS OS from axis.com, Read the AXIS OS status, Upload AXIS OS to the device, Install
AXIS OS, Wait for the device to come back, Verify version, Read commit state, Commit AXIS OS.

**Download AXIS OS from axis.com** shows the progress, for example "68 of 225 MB". It is skipped for a file you chose. When your
MyAxis sign-in has expired, the task ends before the device changes: sign in again and run it again.

The device waits up to 30 minutes for the commit. If OADM never confirms the new version, the device rolls back to the
old version by itself. After a factory default the device commits by itself and the task ends with a warning: set a
password or check the address.

**Cancel** after the upload does not stop the device. It still starts the new version, rolls back to the old version by
itself 30 minutes later and restarts. With a factory default it installs the new version and resets.

<Aside>
At most 4 devices upgrade at the same time, because every upload sends 100 to 250 MB from the server. The other tasks
wait in **Queued**.
</Aside>

## Task names

The **Tasks** pane names each task by what it does: "Upgrade AXIS OS to 12.11.77", "Downgrade AXIS OS to 10.12.236",
"Install AXIS OS 12.11.77", plus " (factory default)" when the device is reset. With files of different versions:
"Upgrade AXIS OS" or "Downgrade AXIS OS".
