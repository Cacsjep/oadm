## Columns

| Column | Shows |
|---|---|
| Icon | Device type. Amber or red when the device needs attention. Click it on a camera for the [live preview](../live-view/). |
| Address | IP address or host name. Click it to open the device's web interface. |
| Model, MAC address, Firmware | From the device. |
| SoC | The chip of the device, short: A8 for ARTPEC-8, CV25 for Ambarella CV25. The search finds both names. Off by default. |
| Status | OK, Unreachable, Credentials required, Password not set, Certificate changed, Site offline. |
| Tags | Your [tags](../tags/). |
| Site | The [site](../../sites/overview/) the device is at. |
| HTTPS, IEEE 802.1X | Whether they are on. Off by default. |
| DHCP | Whether the device takes its address from DHCP. Off by default. |
| Certificate expires | Days left for the HTTPS certificate. Amber within the days of its expiry warning on the PKI page (30 by default), red when expired. |
| Certificate | Trusted, Self-signed, Untrusted or Expired. |
| Clock | OK, or an amber warning icon when the device clock differs from the OADM server by more than the allowed clock difference in **Settings** (2 s by default) or NTP is not synced. Hover it to see how far. The export has the difference. |
| Compliance | The worst result of the [compliance checks](../compliance/). Off by default. |
| Vulnerabilities | The published Axis CVEs the device's firmware may be affected by: the count and the worst severity, red for High and Critical, amber for Medium. Hover it for each CVE and the firmware that fixes it on the device's track. See [Vulnerabilities](#vulnerabilities). |
| Architecture | The processor type, for example aarch64. Off by default. |

Click a header to sort. Choose columns with the columns button right of the toolbar. Order and widths are kept per
computer. OADM checks every device, waits 60 seconds after each round and checks again; it reads all details in rounds
with a 10 minute pause, and at once after a task, a new firmware or when a device is back. A device that does not answer
within 3 s is asked once more before it shows Unreachable. Large installations need no settings for this.

## Toolbar

- **Add**: [Add devices](../add/).
- **Remove**, **Refresh**, **Export** (the selected devices, or every device the search shows, as CSV).
- **Restart**, **Upgrade firmware**, **Assign IP address** and **System report** for the selection.
- On the right: AXIS OS release notes, **Group by tag**, columns and search. The search also finds tags.

Entries that do not fit move into the **More** menu.

## Context menu

<Image src={menu} alt="Context menu with group submenus" class="screen" />

Right-click one or more devices:

- **Open web interface**, **Refresh**, **Tags**.
- **Log in**: only for devices that reject the stored password. Enter the right one for all of them at once.
- **Set password**: only for factory-default devices.
- **Trust new certificate**: only for devices with **Certificate changed**. Shows the certificate each device presents
  now; **Trust** keeps the device with its tags and history. Trust it only if you know why it changed.
- **Vulnerabilities**: only when a selected device has known CVEs. See [Vulnerabilities](#vulnerabilities).
- One submenu per group with the [device tasks](../../tasks/overview/). An entry the selection cannot run is grey;
  hover it to see why.
- **OADM** > **RTSP port**: the port OADM uses for live view and events of cameras behind a port forward. Nothing is
  changed on the camera.
- **Remove**, last.

## Certificate changed

When a device presents another HTTPS certificate than the one OADM saved when adding it, the status is
**Certificate changed** and OADM sends nothing to it. Once you know why it changed, right-click it and use **Trust new
certificate**.

## Vulnerabilities

<Image src={vulnerabilities} alt="Vulnerabilities window for several devices" class="screen" />

OADM knows the published Axis CVEs of AXIS OS and other Axis device firmware. It matches them by model, firmware
version and chip, so a device "may be affected": whether the affected feature is in use is not known.

- **Vulnerabilities column**: the count and the worst level of the device, for example 2 · High. Hover it for each CVE.
- **Search**: type a CVE ID, for example CVE-2024-6509, to see the devices it may affect.
- **Vulnerabilities window**: right-click one or more devices and choose **Vulnerabilities**. Each CVE is listed once,
  worst first, with its level, score, the firmware that fixes it, the full description and **Advisory**, the Axis
  security advisory. With several devices, **Devices** says how many of them it affects; hover the number to see which.

**Fixed in** is the first fixed version on the device's firmware track. When Axis lists no fix for that track, it is the
first fixed version of a newer track. Upgrade to that version or later.

Every release ships the list of its day. To get new CVEs between releases, turn on **Update the list online** in
[Settings](../../admin/settings/).
