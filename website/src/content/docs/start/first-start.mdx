<Steps>

1. Install OADM on the computer that runs the server. The service starts on its own.

2. Start the client. On its first start on this computer it shows the terms of use: **Accept** to continue, **Quit**
   to close it. Then it connects to `localhost:5080`. For a server on another computer enter `<server>:5080`.

   <Image src={terms} alt="The terms of use on the first start" class="screen small" />

   <Image src={login} alt="Login window" class="screen small" />

3. On the first connection the client asks **Trust this server?**. Click **Trust server** if it is your OADM server. To
   check it, open **Fingerprint** and compare it with the line "Server TLS certificate fingerprint" in the server log.
   The client remembers the server from now on.

   <Image src={trust} alt="Trust this server? with the fingerprint open" class="screen small" />

4. While the server has no users, the login window creates the **first administrator**. From another computer you
   also need the setup code from `setup-code.txt` in the server's data folder (it is in the server log too).

   <Image src={firstAdmin} alt="Create the first administrator" class="screen small" />

5. Open **Credentials** in the navigation rail and add the passwords you use on your devices.

6. On the Devices page click **Add** and choose **Discovery**, **Network range**, **Add manually** or
   **Import from file**. OADM logs in to every device it finds with your credentials. See
   [Add devices](../../devices/add/).

</Steps>

<Aside type="tip">
Add more people on the **Permissions** page. Operators work with devices and tasks; administrators also change settings,
users and the NTP and DHCP servers. See [Users and roles](../../admin/users/).
</Aside>

<Aside type="tip">
To see two tools at the same time, right-click a tool in the navigation rail (for example the I/O Monitor) and choose
**Open in new window**.
</Aside>

## When the login stops

A problem shows as a box below its field:

- **Cannot reach the server**: check the address and that the server runs, then click **Try again**.
- **The server certificate changed**: the server got a new certificate, for example after a reinstall. Click
  **Forget server**, then trust it again.
- **Login locked**: too many wrong passwords. Wait the minutes it says.

<Image src={unreachable} alt="Cannot reach the server below the server field" class="screen small" />

## New versions

When a newer OADM version is out, the client says so after you log in. **What's new** lists the changes, **Open download
page** opens the download page. Tick **Don't tell me about new versions** to stop it; turn it on again in
[Settings](../../admin/settings/) > Client.

<Image src={update} alt="A new OADM version is available" class="screen small" />

## Start options

- `--server <server>:5080` preselects a server in the login window.
- **Remember me** keeps you logged in on this computer. The password is never saved.
